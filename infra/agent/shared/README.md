# Optional shared-host Agent backend

This is a new explicit backend. The dedicated Docker backend's UID10001, network and host guards remain unchanged. Do not run Docker or mount its socket for this backend. Do not use the Core/music UID, operator UID or docker group. Never copy Core configuration or model homes into a workspace.

Provision rootless Podman with its normal packaged user-namespace helpers and systemd cgroups v2 for a distinct `rooms-ai` Linux user (UID>=1000, not10001). Give it a private home and subordinate UID/GID ranges, no sudo and no Core file groups. Install the user unit and enable its normal systemd user manager. Rootless Podman's container scopes and the broker must both descend from `user-<uid>.slice`. Install `user-slice.conf` as a root-owned system drop-in on that exact user slice; apply it before starting. The runtime checks the actual ancestor memory/CPU/process limits, root ownership, process location and Podman rootless/cgroup mode. A misconfigured host fails closed.

Provision a separate persistent ext4 workspace filesystem, at most2GiB TOTAL across retained tasks. This is deliberately stricter than the2GiB per-task ceiling and bounds direct file tools as well as containers. Use a dedicated root-owned image, e.g. `truncate -s 2G`, `mkfs.ext4`, and a root-owned mount unit based on the example. Mount at `/var/lib/rooms-agent/workspaces`, with `nosuid,nodev`; set the mounted directory owner to rooms-ai and mode0700. The parent service data directory is private to rooms-ai; the image directory is root-only. Back up existing workspaces before any migration. Never format an existing filesystem. The service verifies an actual ext4 mount point, size and private ownership. ENOSPC must be handled as a task error; no task data is deleted automatically.

Use the existing private authorization file, encrypted Agent storage key and API model connection flow. Set `ROOMS_AGENT_BACKEND=shared-rootless`, `ROOMS_AGENT_DATA=/var/lib/rooms-agent` and `ROOMS_AGENT_WORKER_IMAGE` to a locally installed image pinned by sha256 digest. Provision/pull the image outside the Agent process. The runtime never pulls images. It only accepts the task's exact workspace bind; no model homes, provider keys, host paths, Docker socket or caller-controlled container flags are accepted.

Workers have no network, readonly rootfs, private PID/IPC, dropped capabilities, no-new-privileges, mapped nonroot UID10001,128PIDs,512MiB RAM/no extra swap and0.5CPU. Shell tool input/output is bounded. Only API-backed models are supported in this mode: CLI model homes, browser workers and worker egress are unavailable. API credentials stay in the broker's encrypted model store and are never injected into shell environments. The broker can only use explicitly configured external connectors under existing approval/checkpoint policy; leave these unconfigured initially.

One task runs at a time. A continuous60s actual CPU window plus availableRAM>=1GiB/diskfree>=6GiB is required before admission. A telemetry gap, low memory or sustainedCPU>90%/30s interrupts execution; duration is15minutes. Interrupted mutating commands retain the existing uncertain-operation checkpoint and require result verification, never automatic replay. Cancellation waits for rootless container removal, including a creation/cancellation race. The2GiB workspace volume is measured separately from the host disk's6GiB admission reserve.

Acceptance: actual rootless worker, enforced ancestor/container limits, private host-file/network denial, persistence and quota failure, stop/timeout, uncertain-effect recovery, and measured voice/DJ coexistence. Unit tests alone do not certify this backend. Human/AI shared PTY and HostOps grant integration are separate outstanding work; this backend does not enable `agentAvailable` by itself.

Rollback: stop only this dedicated user's Agent unit and revoke its Agent grants; preserve encrypted data, volume and encryption key. Do not stop Core or delete workspaces. Existing dedicated deployment remains available unchanged.

References: [Podman run](https://docs.podman.io/en/v5.6.1/markdown/podman-run.1.html), [rootless tutorial](https://github.com/containers/podman/blob/main/docs/tutorials/rootless_tutorial.md).

## Host grant and workspace terminal wiring

Shared mode now also requires `ROOMS_AGENT_HOST_ID` and `ROOMS_AGENT_HOST_AUTHORITY_KEY` (64hex private random bytes, generated outside Git). Configure the same private key in HostOps `agentAuthority.key`, with a dedicated read-only community bot token in `agentAuthority.botToken`. Its role only needs to read the community and current membership; it needs no channel-write, music or provider permissions. Rootless Agent queries the loopback-only `/internal/agent-authority` endpoint. Keep that path out of the public reverse proxy. Owner/current-member and host-specific Agent grant are checked independently from the existing per-person Agent bearer/model/room policy. Every active task and terminal rechecks authority; a revoked detached human shell is terminated as well. Missing authority configuration fails closed.

Set `ROOMS_AGENT_NATIVE_MODULES` to the root-owned native node-pty kit to enable workspace terminals. Build for the same Node ABI as the Agent service. A human workspace shell uses a persistent rootless TTY container, only the selected task volume, the same container resource limits and no network. It survives panel/broker disconnect, subject to the24h terminal expiry; reboot/container exit is an interruption. At most one human workspace container exists at a time within the aggregate budget. It never uses the operator-host terminal helper, Linux profile, sudo or a Core mount.

A takeover waits for the whole AI task and actual worker removal before creating that shell. AI and human share task files, with explicitly separate process contexts: this does not pretend an ephemeral AI command's shell variables survive in the human shell. A live human shell prevents another AI task from starting. Terminate the shell before requesting continuation; continuation returns to approval, and uncertain mutating operations still need verified resolution. Account/frame/task/connection fences and one-connection writing protect the native stream. Output is bounded in memory without transcript files.

The task view reports actual logical host/workspace/terminal associations, selected provider and verified configured resource ceilings. These are limits, not measured utilization or fabricated completion percentages. Physical voice/DJ coexistence and native rootless PTY acceptance remain rollout gates.
