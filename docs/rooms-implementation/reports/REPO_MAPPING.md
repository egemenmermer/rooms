## Existing architecture and boundaries

Electron 44 + React 19/TypeScript/Vite + React Router, pnpm workspace (`pnpm@11.25.0`), Zustand preferences/community stores, real module-scoped LiveKit provider. `App.tsx` owns `/home`, `/spaces`, `/chat`, `/voice`, `/cinema`, `/youtube`, `/games`, `/together`, `/agent`; `/polls` redirects to polls and `/settings` overlays the previous route. Unknown paths redirect to Home. `/chat` identifies channel/DM via `community.activeChannelId`, not path parameters. Member/friends/invitation/editor/task surfaces are local modal state, not dedicated routes.

`packages/shared-contracts/src/index.ts` defines `DesktopBridge`; `electron/preload.ts` exposes narrow typed operations. Electron main validates sender/input and controls native permissions, source lists, provider credential vaults, session restore, updates, attachment selection, and export. `electron/community.ts` binds actual `StoatClient` from `packages/stoat-adapter`, stores the auth session using `safeStorage`, and translates gateway events into `community.ts`. Legacy Spacebar remains separate and must not replace Stoat. Personal provider metadata is exposed through `providers`, private playback uses native protocol access, agent authentication/config is handled by main, and model secrets belong to the separate agent server.

`realtime.ts` owns `useVoiceContext` + singleton `liveKitMediaProvider`; navigation components subscribe without creating/disconnecting transports. Only explicit `joinVoice`/`leaveVoice` changes room lifetime; `joinVoice` intentionally leaves the previous room before obtaining an actual channel grant. Capture calls use main's enumerated selection and server presenter acquisition. Keep this lifetime independent of App route, settings overlay, Activity unmount, and main activity end. Activity service uses revisioned commands and server filtering for game hands; preserve actual grants/roles/singleton enforcement rather than introducing route-local authority.

Scripts exist for dev, build, typecheck, unit/desktop tests and service integrations in `package.json`; none were run here. `pnpm build` itself invokes typecheck before Vite/Electron builds. Current dirty tree observed during concurrent work includes reference-brand and reference-tokens assets, owned by another task. No source files modified here.

## Architectural gaps to resolve centrally

- Add reference state-to-entry mapping/development scenario harness; no production prototype iframe/image replacement. Separate layout/state verification from `REAL` service evidence.
- Replace shell dimensions/hierarchy centrally; authenticated and signed-out shell currently diverge. Use the package's exact breakpoint behavior, minimum 900×700, and real sidebar drawer without global zoom.
- Separate chat header from generic shell toolbar; create room context inspector based on allowed members rather than friendship roster. Extend domain/adapter capabilities for message search, typing, richer reactions and reference permissions only if upstream provides enforceable semantics.
- Add dedicated DM call context and grant/return contract. The existing native media bridge grants channel IDs; a DM UI must not pretend that a voice-channel session is the correct private recipient call.
- Cinema is currently personal local-file playback; generic activity protocol supports cinema/player state but reference private-source identity matching, per-user readiness/buffering, synchronized playback and mode separation are absent. Shared source publication exists through LiveKit voice. Preserve privacy: URLs/paths/tokens cannot enter shared state. Coordinator transfer cannot recreate another device's capture.
- Community create/edit/roles and role/member channel permissions are absent from DesktopBridge. Access service enforces permissions; a local visual permission editor does not constitute mutation support. Recovery/account deletion/password change similarly need actual upstream native contracts.
- Server GitHub/Drive tools and Discord bot code exist, but desktop connection/revoke/scopes and bot status/configuration/history endpoints are missing. Keep assistant mention/initiator/personal model semantics, normal approval and current server-managed YOLO authority. Do not invent OAuth success UI.
- Keep game rules, hidden-hand filtering, reclaim and turn timers server-owned. There are actual engine modules for all four games; reference layout can reuse commands. Source evidence: `packages/games/src/seats.ts` sets `TURN_DURATION_MS = 45000`; `apps/services/activities/games.ts` applies 30000 ms bot takeover and turn-boundary pendingReturn. Exact brief rule defaults and runtime 30s/45s behavior still require explicit checks, not frontend approximation.
- Native notifications/updater/privacy export exist; an inbox/notification history, compact native player/call window and dedicated About/licenses surface do not. Native capability errors and unavailable updater feed/signing must remain honest.
