# Spotify playlist import

The DJ input and Shared Playlists import accept public `open.spotify.com/playlist/<id>` URLs, including localized links and share parameters. Track order and duplicate entries are preserved. Spotify supplies display metadata only; the existing YouTube matcher and room publisher supply audio. No Spotify credentials, cookies, previews, or client-side player are used.

Public embed metadata is bounded to 2 MiB and a 12-second request. Empty or unavailable lists fail with a specific message. Adding a link in the DJ input is a partial import: the public embed shows at most 100 entries, so a list exposing 100 or more is imported up to that cap, and podcast, local-file or malformed entries are skipped. A list with no readable track still fails. The add response carries `importNotice` (`added`, `skipped`, `truncated`) and the DJ panel shows it as a neutral info line, so a cut is never silent. Only the room left in the queue is added: played and current tracks stay in the queue, the rest of the list is cut (reported as truncated) and `MUSIC_QUEUE_FULL` is returned only when nothing fits. Shared Playlists import stays strict: lists of 100 or more entries and any unreadable entry fail the whole import. `spotify.link` short links are followed (hosts `spotify.link` and `open.spotify.com` only) and routed to the playlist or single-track path; short links to anything else are rejected. Private playlists and albums are not supported. The room queue holds at most 100 tracks in total. Importing a complete 100+ list would need the Spotify Web API and credentials, which is not implemented.

Each Spotify track is matched only when selected for playback. Once a list is inserted, a playback error remains attached to the queue snapshot; retrying an import is not required. Users can select another track or advance past an unmatched entry. Completed audio advances to the next track through the existing publisher callback. Stopping or losing the session during matching prevents late audio publication.

Pending Spotify tracks are retained in shared lists and DJ history as validated IDs and display metadata, without private source addresses. Existing YouTube history remains readable. Shared playlist records and persisted history now accept Spotify records as well as YouTube records: deploy the Access service, music worker and desktop client together. `importNotice` is a new field in the strict music snapshot schema, so the same applies to it. Old clients cannot parse shared lists containing the new records, and old workers cannot read history containing them. Back up history and shared-list storage before deployment; a rollback requires restoring the corresponding storage backup.

Validation covers public metadata parsing, ordering/duplicates, invalid and truncated lists, lazy matching, natural-end advancement, stopped-session fencing, queue capacity, playlist persistence and desktop import/play commands. Live room audio remains a separate deployment check: import a public playlist, confirm the visible count/order, hear the first song from a second participant, then verify next/select and a natural track ending.
