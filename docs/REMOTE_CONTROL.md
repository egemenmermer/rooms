# Consented desktop control

ROOMS separates presentation handoff from OS input consent. A human viewer requests control of an actual published screen track. The publisher approves in a native confirmation dialog for the currently selected full monitor. Window capture, bots, Agent tasks, clipboard synchronization, file transfer and unattended access have no input route.

The Access service binds each ephemeral request/approval to the room, publisher/controller identities and LiveKit participant SIDs, actual screen track SID and a fresh native capture epoch. A rejoin, new capture, track/membership loss or service restart requires a new decision. Only the publisher heartbeat extends the5second lease. Native main requires verification within2.5seconds and refuses slow/stale authority responses. Reconnect cannot reactivate a previously used approval.

The32byte input key is returned only to the two involved native clients and retained in main memory. The preload exposes a strict projection without that key. Main signs packets only for the requesting controller's current lease; old UI queues cannot sign for a new lease. The renderer only transports signed bounded packets over a targeted LiveKit data channel. Main verifies the HMAC, source epoch, lease, expiry, timestamp, sequence and rate before native input. Mouse motion uses a separate lossy sequence; keys/buttons are reliable. Other members do not receive an input key. Data publication is enabled only after consent and preserves microphone/camera/screen permissions; normal/rejoined room grants have data publication disabled.

Mac uses CoreGraphics input and an event tap with normal Accessibility/Input Monitoring permissions. Windows uses SendInput, low-level input hooks and normal desktop/UIPI restrictions; it never elevates or crosses a secure desktop. Native input begins only with actual current monitor geometry. Electron's display_id selects the Display; Windows DIP coordinates are converted to physical pixels and checked against native monitor bounds. Input coordinates remain within that monitor. Key-down is refused if the focused application window is outside the selected monitor: click a visible window first. Some OS-reserved shortcuts cannot be forwarded by a renderer.

Publisher local mouse/keyboard activity ends control and releases held keys/buttons. The native module also releases them on stop/failure/cleanup. The global emergency shortcut is Control+Alt+Shift+K (Control+Option+Shift+K on Mac); failure to reserve it prevents activation. Viewer blur, source selection, room/account changes, network/heartbeat loss and display geometry changes revoke control. The UI shows the active controller and a release action. Authenticated ping/pong measures actual data-channel round-trip latency; it is not a claim about total video encoding/input-to-display delay.

Build the independent N-API module with `node scripts/prepare-remote-input.mjs` on Mac or from a Visual Studio x64 developer shell on Windows. Official Electron SDK inputs are pinned by SHA256 when downloaded. Release/package paths include the module, corresponding source and verify source/platform/architecture metadata. Build/load smoke never arms a monitor, installs hooks or sends input; its unapproved key call must returnfalse.

## Acceptance

Source tests cover human-only consent, publisher authority, hidden keys, source/SID/track/epoch changes, membership/rejoin/expiry, HMAC tampering/replay, independent lossy/reliable sequences, stale UI leases, native-dialog races, passive expiry, transport latency and voice-permission preservation. Native fixture tests are labeled injected fixtures, not physical OS control.

Before production acceptance, use two physical clients: Mac↔Mac and Mac↔Windows, both publishing and controlling. Verify explicit deny/approve, full-monitor-only selection, multiple monitors/negative origins/DPI scaling, visible focused-window typing, dragging/scrolling, modifier release, publisher local takeover, emergency shortcut, viewer blur, network/rejoin/member revocation, source stop/change and secure-desktop denial. Verify voice/DJ/screen coexistence. Record real latency, outcomes and OS permission setup. Do not close this gate from CI or publish an accepted release before the participants test it.

Rollback removes this client capability/new Access routes and revokes ephemeral leases. Existing screen sharing, music, accounts and user data remain independent. Never disable OS protections or broaden screen permissions to hide a failure.
