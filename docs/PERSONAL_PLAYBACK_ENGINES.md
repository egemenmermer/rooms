# Personal IPTV playback follow-up

Owner reports missing human category names, intermittent playback, stalls and opaque failures. The same failing channel plays continuously in the owner's VLC test. This narrows investigation to the ROOMS playback path; it does not identify a specific codec or rule out differences in requests to the provider. No private provider URL/account was supplied or inspected.

Source fixes accept standard, wrapped and keyed Xtream category responses and normalize decimal identifiers without lossy numeric conversion. Inline category names are used when category metadata is unavailable. Unresolved names are labeled explicitly rather than presenting internal numbers as human group names. Live waiting/stalled events now have a bounded watchdog, cancel on real progress/pause/account disposal, and use existing bounded HLS recovery. Unknown failures no longer imply that the account or source is invalid. These changes do not certify playback of the reported channel.

## Native-engine direction

Use libVLC as a candidate native personal-media backend while retaining ROOMS navigation and controls. Official embedding interfaces provide macOS NSView and Windows HWND surfaces. The current HTML/HLS path already delegates decoding to Chromium/hls.js; it is not a new decoder written from scratch. A VLC backend can expand supported formats, but provider failures and category metadata still require their own handling.

Do not connect the renderer directly to libVLC with provider credentials. Reuse the current native provider authority, account epochs, bounded network validation, handle revocation and local-only playback. VLC does not understand `rooms-provider:`; an authorized loopback streaming adapter must translate that capability and rewritten playlist/segment URLs without exposing the original provider credentials or enabling arbitrary file/network access. Engine logs/events must omit source URLs and authorization data.

Evaluate a pinned native binding and matching ARM64/x64 libVLC runtime before adoption. The reviewed electron-vlc-player wrapper does not bundle libVLC and documents a fixed container with no page scrolling; its native window/overlay lifecycle cannot be assumed to fit the current UI unchanged. Validate resize/fullscreen, controls, route hide/return, stop/account switch, crashes, audio/video track selection and actual sustained playback on both platforms. Distribute licenses/notices and required source/relinking materials for the selected runtime/plugins; do not assume every VLC binary/plugin shares one license.

## Current native implementation (candidate only)

The third-party Electron wrapper was rejected by pnpm's exotic-subdependency policy because its rebuild chain requested a Git-hosted node-gyp dependency. The policy was left enabled. That wrapper and its code were not installed, vendored or compiled. ROOMS now has an independent small N-API adapter written against VideoLAN's official libVLC 3 C API; it does not add an npm dependency.

`pnpm prepare:vlc` verifies pinned VLC 3.0.23 and dependency source checksums, builds the macOS engine from source, compiles the adapter and retains licenses/notices. The source build uses FFmpeg 7.1.5, libdvbpsi 1.3.3 with VideoLAN’s security patches, libgcrypt 1.12.0/libgpg-error 1.58 and FreeType 2.14.1. A small avcodec version-guard correction supports building without avformat. The official macOS binary distribution was rejected by the unchanged privacy guard because it embeds builder home-directory paths; it is preserved only for local review and is not packaged. The macOS ARM64 runtime and Windows x64 runtime use their own host compiler; Windows requires a Visual Studio x64 developer shell. Official Electron SDK inputs are checksum-pinned. The generated output is outside Git. `ROOMS_VLC=1` includes this engine in application packaging; absence leaves the existing Chromium/HLS player available. The personal-player options retain an explicit Standard player choice; no automatic concurrent provider-stream fallback is started.

All playback starts with an existing account-scoped provider capability. The native engine sees only a random-capability server bound to 127.0.0.1. The main process proxies requests through existing provider network/redirect/range validation, rewrites HLS children, rejects unresolved playlists and unsupported root reference containers, and aborts reads at revocation. Provider addresses, credentials, local capability URLs and native window handles are never returned to the renderer. Window bounds are clamped; stale React tokens cannot operate or stop replacement playback. Initialization and blocking libVLC stop/release run asynchronously. Scope polling also revokes paused playback. Closing the native window revokes the player.

The existing renderer navigation, EPG and controls remain. Video appears after libVLC reports displayed frames, not merely after metadata load. Native drawing is bounded above the DOM controls, preventing visually obscured but technically clickable buttons; fullscreen Escape has an explicit handler. libVLC ignores the standalone VLC application’s user configuration. The native surface hides on route change, modal/menu display, minimization and player disposal. Live DVR controls remain unavailable when libVLC supplies no reliable live seek interval; users can explicitly choose Standard for sources that supply such an interval. This adapter is for local personal playback and does not add provider-content broadcasting.

The LGPL shared engine and its source are replaceable; bundled plugins may have GPL or other licenses. Archive/source links, COPYING, COPYING.LIB, AUTHORS, THANKS and official distribution notices accompany the runtime, along with the ROOMS adapter source/build script. Before a release, verify both platform packages, actual output/controls/resize/fullscreen, account/window cancellation and the owner's reported sustained IPTV playback. Synthetic-media and mock checks do not close real-provider or physical-device acceptance. The initial implementation was held as a candidate; see the RC9 rollout record below.

Primary references: [VideoLAN source and engine licensing](https://github.com/videolan/vlc), [official libVLC media-player interfaces](https://videolan.videolan.me/vlc-3.0/group__libvlc__media__player.html), [reviewed Electron binding requirements](https://github.com/ssnangua/electron-vlc-player).

## Current validation

The source-built macOS engine passed the unchanged private-literal guard and the macOS minimum-version audit (all native libraries support 14.0). The actual unsigned macOS application package, including loose native resources, passed the public package guard. This does not certify signing/notarization or the Windows candidate.

Real synthetic AVI/PCM playback produced decoded/displayed video frames and audio-output buffers. Native pause/resume, bounds API and asynchronous stop passed. The actual PersonalPlaybackRuntime UI with an isolated synthetic account/source passed first-frame control readiness, pause/volume/options, route hide/return, fullscreen/Escape and 900×700 document overflow checks. A native window screenshot was visually inspected; the control overlap it exposed was corrected and recaptured. These receipts are private generated test evidence. The reported real provider channel, sustained IPTV, signed cold-start behavior and physical Windows/two-client acceptance remain release gates. Those candidate checks did not publish a release or modify the owner installation; see the later RC9 rollout below.

The corresponding-source archive was generated from six checksum-verified upstream archives plus the adapter, build scripts and patch. It must be regenerated for the final release version and distributed beside its installers. The complete source suite passed 130 files / 855 tests, followed by two additional passing initialization/account-revocation race regressions. Lint, type checking and service builds passed. Platform CI was pending at that point; the native integration subsequently passed both package-resource jobs.

Additional native transport regression: a generated H.264/AAC MPEG-TS initially produced no output because the TS plugin could not resolve bundled libdvbpsi through the adapter’s rpath. Bundled plugin/library references now resolve relative to each loading binary. The same generated transport stream then produced video frames and audio buffers and passed pause/resume/stop. This is separate from the successful raw AVI test and is still not owner-provider acceptance. The native check uses a visible isolated test window: hidden-window frame rendering proved intermittent. Linux unit fixtures explicitly emulate a supported desktop platform without enabling production Linux playback.

RC9 candidate validation after the transport fix: the full suite passed 130 files / 859 tests. The local synthetic HLS/H.264/AAC check also passed with displayed video frames, audio-output buffers and a six-second seekable timeline. At that validation point RC9 was held as a test candidate and RC8 remained installed/live.

Hosted macOS CI produced 151 decoded frames and audio buffers but zero compositor display frames. The explicit hosted `ROOMS_VLC_QA_OUTPUT=decode` check certifies decoding/audio/API lifecycle and records compositor acceptance as excluded. The default local check still requires displayed frames. This distinction does not replace required actual visible-player checks. The signed packaged RC9 application passed synthetic HLS video/audio in a separate empty profile, with first display at 2,761 ms; Apple notarization, stapling and Gatekeeper passed. No owner-provider playback or general release is inferred from these results. Candidate application source is immutable 8f95ac1.
